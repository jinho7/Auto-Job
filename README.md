# Auto-Job

채용 공고 수집 → Notion 정리 → 지원서 작성(인적사항 + 자기소개서) → **임시저장**까지 AI가 처리하는 취업 자동화 도구.
최종 제출은 항상 사람이 합니다. 설계와 로드맵은 [PLAN.md](PLAN.md)에 있습니다.

> **English:** Auto-Job collects Korean job postings, files them in Notion, and fills in application forms
> (personal details + cover-letter answers) with an AI agent, stopping at **save-as-draft** — it never submits.
> Everything runs on your own machine with your own AI account; docs are in Korean. MIT licensed.

> 현재 단계: **v1 기능 완료** — 공고 수집 → Notion 등록 → 지원서 작성(인적사항, 자기소개서) → 임시저장 → Notion 정리.
> 실제 채용 사이트마다 화면이 달라, 처음 몇 곳은 결과를 꼭 검토해 주세요.
> 내 정보와 설정은 모두 내 컴퓨터에만 저장되고, 다른 사람도 자기 정보로 그대로 쓸 수 있게 만들었습니다.

## 준비물
| 무엇 | 설명 |
|---|---|
| 컴퓨터 | macOS (주로 확인한 환경), Windows, Linux |
| [Node.js](https://nodejs.org) 22 이상, Git | 설치 확인: `node -v`, `git --version` |
| 브라우저 | [Aside](https://aside.com) 또는 Google Chrome. 평소 프로필과 분리된 **자동화 전용 프로필**을 따로 씁니다 |
| AI (하나) | 아래 "AI 연결 방식" 참고. 가장 쉬운 것은 Claude Code |
| Notion (선택) | 공고를 정리할 DB. 없어도 수집 미리보기와 지원서 작성은 됩니다 |

### AI 연결 방식
공고 판단, 지원서 입력, 자기소개서에 쓸 AI 를 고릅니다. 어느 것을 써도 브라우저 도구와 **제출 차단은 똑같이 코드로 적용**됩니다.
**여러 개를 연결해 두면 돌려씁니다** (설정 → AI 연결): 위에서부터 쓰고, 사용량 한도나 로그인 문제가 생기면 다음 연결로 넘어가 이어서 합니다. 한도에 걸린 연결은 풀리는 시각까지 쉬었다가 다시 씁니다. 같은 Claude Code / Codex 를 한 번 더 추가하면 따로 로그인하는 계정 폴더가 생겨 **다른 계정도 돌려쓸 수 있습니다** ("로그인하기" 버튼이 터미널을 열어 줍니다).

| 방식 | 필요한 것 | 비용 | 확인 상태 |
|---|---|---|---|
| Claude Code (`claude-cli`, 기본) | [Claude Code](https://claude.com/claude-code) 설치 후 `claude` 를 한 번 실행해 로그인 | Claude 구독 (Pro/Max) | ✅ 실제로 전체 흐름 확인 |
| Codex CLI (`codex-cli`) | `npm i -g @openai/codex` 후 `codex login` | ChatGPT 구독 | 🧪 실험적 (가짜 codex 로만 확인) |
| Anthropic API (`anthropic-api`) | API 키 | 쓴 만큼 | 🧪 가짜 응답으로만 확인 |
| OpenAI API (`openai-api`) | API 키 | 쓴 만큼 | 🧪 가짜 응답으로만 확인 |

## 설치

```bash
git clone <이 저장소 주소> Auto-Job
cd Auto-Job
npm install
npm link          # 선택: 어디서든 `autojob` 명령 사용
autojob init      # 설정 파일을 만들고, 설정을 차례대로 안내합니다
```

- `npm link` 를 하지 않았거나 Windows 라면 `autojob …` 대신 `npm run autojob -- …` 로 실행합니다 (예: `npm run autojob -- doctor`).
- `autojob init` 은 설치된 브라우저(Aside, Chrome)를 찾아 브라우저 설정을 맞춥니다. 이미 있는 설정 파일은 건드리지 않습니다.

## 처음 쓰는 순서
`autojob init` 에서 **설정 화면**을 고르면 브라우저에 설정 화면이 열리고, **시작하기** 목록이 남은 할 일을 보여 줍니다. 터미널에서 차례대로 할 수도 있습니다.

1. **AI 연결** — 방식을 고르고 "연결 확인"을 누릅니다.
2. **내 정보** — 가지고 있는 이력서나 지원서 메모를 **📋 붙여넣어 채우기**에 통째로 붙여넣으면 AI 가 항목별로 나눠 줍니다. 미리보기를 보고 적용합니다. 없는 값은 비워 둡니다 (AI 가 추정해서 채우지 않습니다). 증명사진은 같은 화면에서 올립니다 (끌어다 놓기 가능).
   **자기소개서 소재**는 경험을 정리해 둔 폴더를 연결합니다 (내 정보 → 자기소개서 소재 → 폴더 고르기).
3. **검색 키워드 · 수집 사이트 · 기업 구분** — 예: 키워드 "백엔드", 중소기업 제외.
4. **Notion** (선택) — 화면의 안내대로 통합(토큰)을 만들고, 공고를 정리할 DB 를 고르거나 **같은 구조의 DB 를 새로 만듭니다**.
5. **브라우저** — "자동화 브라우저 열기"로 창을 열고 자주 쓰는 채용 사이트에 로그인해 둡니다 (로그인은 유지됩니다).
6. **점검** — `autojob doctor` (AI 가 실제로 답하는지까지 보려면 `autojob doctor --ai`).
7. **공고 수집** — `autojob collect --dry-run --limit 5` 로 미리 보고, 괜찮으면 `autojob collect`.
8. **지원서 작성** — 설정 화면의 **실행 → 지원서 작성**에서 Notion 공고를 최대 8개 골라 맡깁니다 (터미널은 `autojob apply "<Notion 공고 페이지>"`). 로그인·본인인증은 직접 하고, 입력과 임시저장은 AI 와 코드가 합니다. **제출은 직접** 합니다.

## 문제 해결
| 증상 | 해결 |
|---|---|
| `autojob: command not found` | `npm link` 를 하거나 `npm run autojob -- <명령>` 으로 실행 |
| `claude 명령을 찾지 못했습니다` / 로그인 오류 | Claude Code 를 설치하고 터미널에서 `claude` 를 실행해 로그인. `autojob doctor --ai` 로 확인 |
| 브라우저가 안 열리거나 연결이 안 됨 | 설정 → 브라우저에서 앱 위치 확인. 다른 프로그램이 같은 포트(9222/9223)를 쓰면 포트를 바꿉니다. `autojob browser test` |
| Notion DB 목록에 내 DB 가 없음 | Notion 에서 DB 가 있는 페이지의 ••• → 연결(Connections) → 만든 통합을 추가 |
| 공고가 0건 | 검색 키워드, 기업 구분(모으기), 마감 기간을 확인. `autojob collect --dry-run --verbose` 로 빠진 이유를 봅니다 |
| 사용량 한도에 걸림 | 한도가 풀린 뒤 다시 실행. 수집의 AI 보강 한도(설정 → AI 보강)를 낮출 수 있습니다 |

## 설정 화면 — `autojob ui`
- 내 컴퓨터(127.0.0.1)에서만 열립니다. 주소에 실행할 때마다 바뀌는 접속 토큰이 붙어 있어서, 다른 웹사이트가 몰래 설정을 바꿀 수 없습니다.
- 입력하면 바로 저장되고, 형식이 틀리면 칸 아래에 이유가 나옵니다.

| 메뉴 | 내용 |
|---|---|
| 시작하기 | 준비 상태 점검 (`autojob doctor` 와 같음)과 "설정하러 가기" |
| 📋 붙여넣어 채우기 | 이력서·지원서 메모를 통째로 붙여넣으면 AI 가 항목별로 나누고, 미리보기(새로/바뀜/형식 문제)를 확인한 뒤 고른 섹션만 적용. 글 속의 입력 지시는 "지원서 입력 규칙"으로, 항목에 없는 정보와 "[비워두기]"는 "지원서 입력 메모"로 |
| 내 정보 (7개 섹션) | `profile/schema.yaml`을 따라 자동으로 만들어지는 입력 화면. 목록 추가/삭제, 증명사진 올리기(미리보기, 끌어다 놓기) |
| 자기소개서 소재 → 소재 폴더 연결 | 경험 정리 폴더(md · txt · pdf)를 연결. 자소서를 쓸 때 AI 가 이 폴더만 읽어 문항에 맞는 소재를 찾음 |
| 검색 키워드 · 수집 사이트 · 고용형태 | 공고 검색 조건 (자소설닷컴·잡코리아 직무 분류는 사이트 목록에서 고르기) |
| AI 보강 | 지원 페이지를 못 찾은 공고의 AI 웹 검색, AI 직무 태그 방식 |
| 기업 구분 · 회사 직접 지정 | 모을 기업 구분과 "작성중" 표시 (자소설닷컴 달력처럼) |
| 자기소개서 문체 | 끝맺음, 소제목, 가운뎃점, 블라인드, 쓰지 않을 표현 |
| Notion | 연결 방법 안내 → 토큰 입력(틀린 토큰은 저장 안 됨) → DB 목록에서 고르기 또는 새로 만들기 → 속성 매칭 검사와 후보 자동 적용 |
| 브라우저 | 기본 브라우저로 맞추기, 평소 프로필의 저장된 비밀번호·로그인 상태 가져오기, 자동화 브라우저 열기(로그인 해두기), 연결 테스트 |
| AI 연결 · 제출 차단 문구 | 여러 AI 연결(순서, 계정별 로그인, 연결별 API 키·모델, 연결 확인, 쉬는 중 해제) / 차단할 버튼 문구 |

토큰과 API 키는 `.env`(권한 600, git 제외)에 저장되고 화면에는 `ntn_abc…wxyz`처럼 가려서만 보입니다.

## 공고 수집 — `autojob collect`
설정 화면의 **실행 → 공고 수집**에서도 같은 일을 할 수 있습니다.

```bash
autojob collect --dry-run --limit 5     # 먼저 미리보기로 확인 (Notion 에 쓰지 않음)
autojob collect                         # 수집하고 Notion 에 등록
autojob collect --list-sources          # 수집기 목록과 상태
```

| 사이트 | 상태 | 방식 |
|---|---|---|
| 사람인 | ✅ | 검색 결과 + 상세 (기업형태, 홈페이지 지원 링크) |
| 자소설닷컴 | ✅ | 자동화 브라우저로 채용 달력 (기업 규모, 채용 사이트 링크) |
| 잡코리아 | ✅ | 채용정보 목록(포함 키워드, 직무 대분류) + 상세 (기업 구분, 홈페이지 지원 링크). 사이트 검색 페이지는 robots.txt 가 막아 쓰지 않음 |
| 캐치 | ✅ | 채용공고 목록 + 상세 (기업 규모, 지원 링크) |
| 원티드 | 조건부 | 자동화 브라우저. robots.txt 를 읽을 수 있을 때만 수집 (지금은 원티드가 robots.txt 요청을 막아 건너뜀) |
| 인크루트 | 수집 안 함 | robots.txt 가 모든 자동 접근을 막음 |

처리 순서: 수집 → 경력직·고용형태·마감 필터 → 이전에 처리한 공고 건너뛰기 → 같은 회사·마감일 공고 합치기 → 기업 구분 → 이미 Notion 에 있는 공고 건너뛰기 → **실제 지원 페이지 확인** → (못 찾으면) **AI 웹 검색** → 직무 태그(규칙 → AI) → Notion 등록(중복 제외) → 리포트(`data/runs/…`)

- robots.txt 를 지키고, `AutoJob/…` 이라는 정직한 이름으로, 요청 사이에 간격(`request_delay_ms`)을 둡니다. 봇 차단은 우회하지 않습니다.
- 기업 구분은 사이트가 알려주는 기업 규모와 설정의 **구분별 회사 목록·회사명 단어**로 정합니다 (설정 → 기업 구분).
- 직무 태그는 설정의 **직무 태그 규칙**으로 먼저 답니다. 규칙이 없는 태그는 태그 이름의 단어로 판단합니다.
- **AI 보강** (설정 → 검색 조건 → AI 보강). Claude Code 가 웹 검색으로 돕고, 사용량이 듭니다.
  - **지원 페이지 찾기:** 공고에 지원 링크가 없거나 열리지 않으면 AI 가 회사 채용 사이트에서 같은 공고를 찾습니다. 찾은 주소는 코드가 다시 열어 확인하고, 카페·블로그 같은 사이트는 인정하지 않습니다. **그래도 못 찾으면 없는 공고로 보고 등록하지 않습니다** (7일 뒤 다시 확인). 한 번에 찾을 최대 공고 수를 정할 수 있습니다.
  - **직무 태그:** 규칙으로 못 단 공고만 AI 가 달거나(기본), 모든 공고를 AI 가 다시 봅니다. DB 에 없는 태그는 버립니다. 태그를 하나도 못 단 공고를 빼는 옵션도 있습니다.

## 지원서 작성 — 설정 화면 또는 `autojob apply`
Notion 공고 페이지(또는 지원 페이지 주소)로 지원서를 열고, 인적사항과 자기소개서를 AI 가 채웁니다. **제출은 하지 않습니다.**

### 설정 화면: 여러 개를 함께 (실행 → 지원서 작성)
- **+ 새 지원서** → Notion 공고 목록(마감 가까운 순, 마감 지난 것 제외)에서 **최대 8개**를 체크합니다. 주소를 직접 넣어도 됩니다.
- 공고마다 **대화방**이 생기고, 브라우저에 **지원서 창이 따로** 열려 뒤에서 진행합니다. 동시에 진행할 개수는 설정(기본 4개)이고 나머지는 차례를 기다립니다.
  - 창은 서로 조금씩 어긋나게 놓이고, 창 제목 앞에 `[지원 1]`, `[지원 2]` 가 붙어 어느 창이 어느 지원서인지 보입니다. 첫 창은 브라우저를 켜면 떠 있는 빈 화면을 그대로 씁니다.
- 대화방에는 AI 가 지금 하는 일(입력한 칸, 비운 칸, 판단 이유)이 계속 올라옵니다.
- 로그인·본인인증처럼 **사람이 해야 할 일이 생기면** 알림이 오고, **그 지원서 창이 맨 앞으로** 뜨고, 대화방에 **빨간 점**이 생깁니다. 대화방에 말로 답하면 이어서 합니다 (비밀번호는 브라우저 창에 직접).
- 끝나면 대화방에 리포트(비워둔 값, 참고사항)가 올라옵니다. **"창 보기"**는 그 지원서 창만 골라 맨 앞으로 올립니다 (다른 창이 위로 올라오지 않습니다). "중지", "방 지우기" 버튼도 있습니다.
- **다 쓴 뒤에도 고칠 수 있습니다.** 대화방에 `3번 문항 더 구체적으로 다시 써 줘`, `학력에 부전공 넣어 줘` 처럼 적으면 **그 창 그대로** 이어서 고칩니다 (로그인은 다시 하지 않습니다).
  적은 말에 따라 자기소개서만 다시 쓸지 인적사항까지 손볼지 정하고, 고쳐 달라고 한 문항은 기존 답을 지우고 새로 넣습니다.
- AI 사용량 한도로 멈췄을 때도 같습니다. 한도가 풀린 뒤 `이어서 해 줘` 라고 적으면 멈춘 곳부터 이어서 합니다. (연결을 여러 개 등록해 두면 한도에 걸리기 전에 다음 연결로 넘어갑니다.)

### 터미널: 하나씩

```bash
autojob apply "https://www.notion.so/…공고 페이지…"                 # 인적사항 + 자기소개서
autojob apply "https://www.notion.so/…" --steps essay               # 자기소개서만
```

1. **준비:** Notion 페이지에서 회사명과 지원 링크를 읽어 자동화 브라우저로 엽니다.
   - **로그인 전에 먼저 정리 (AI, 웹 검색):** 지원 페이지 글과 웹 검색으로 모집 직무·전형 절차·회사 소개를 정리하고, 내 희망 직무에 맞는 **지원 직무를 고릅니다**. Notion 페이지의 **절차 / 회사·조직 소개 / 지원 직무**에 먼저 넣습니다 (이미 내용이 있는 섹션은 둠). 끄려면 설정 → 작성 → 지원서 입력 규칙 → "로그인하기 전에".
2. **로그인 대기 (직접):** 회원가입, 로그인, 본인인증, 약관 동의를 하고 인적사항 입력 화면까지 간 뒤 터미널에서 Enter. AI 는 비밀번호를 보거나 입력하지 않습니다.
   - 자동화 프로필은 평소 프로필과 분리되어 있어 처음에는 저장된 비밀번호가 없습니다. 아직 안 가져왔으면 이 단계에서 가져오라고 알려 줍니다 (설정 → 브라우저).
3. **인적사항 입력 (AI):** Claude Code(`claude -p`)가 `autojob-browser` 도구로만 브라우저를 다룹니다. 내장 도구(Bash, 파일, 웹 등)는 모두 꺼져 있습니다.
   - 이미 값이 있는 칸은 바꾸지 않습니다 (코드로 막음)
   - 제출·작성완료·지원하기, 삭제·로그아웃·작성취소 버튼과 페이지를 떠나는 링크는 누르지 않습니다 (코드로 막음)
   - 내 정보에 없는 값은 비워 두고 **비워둔 Value 값**으로 기록합니다
   - 주소 검색 팝업, 여러 칸으로 나뉜 전화번호, 행 추가 표(학력·어학·자격증)를 다룹니다
   - 사람만 할 수 있는 일(인증, CAPTCHA)이 나오면 멈추고 터미널에서 묻습니다
4. **자기소개서:**
   1. **문항 찾기 (AI + 브라우저):** 문항 글과 글자수 제한(공백 포함/제외, 바이트), 입력칸을 기록합니다.
   2. **소재 찾기 (AI, 소재 폴더만 읽음):** 연결한 폴더의 파일 목록을 보고 문항에 관련 있는 파일을 읽어, 파일에 적힌 사실만 소재로 뽑습니다. 이 단계에서는 웹을 쓰지 않고 폴더 밖 파일은 읽지 못합니다 (Claude Code 기준. 다른 AI 연결 방식은 md · txt 내용을 코드가 붙여 줌).
   3. **조사 → 전략 → 작성 (AI, 웹 검색만):** 회사의 인재상·사업·최근 소식과 직무를 조사하고, 문항 전체를 보고 소재를 1~2개씩 배정한 뒤 씁니다. 사실은 내 정보와 자소서 소재에 있는 것만 씁니다.
   4. **기계 검사 (코드):** 글자수, 쓰지 않을 표현, 가운뎃점, 소제목, 끝맺음, 블라인드(내 이름·학교·동아리명), 반복 글자.
   5. **검토 → 고쳐 쓰기 (AI):** 지어낸 내용, 질문 의도, 구체성, AI 말투, 문항 간 겹침을 검토하고 고쳐 씁니다. 남은 검사 문제는 한 번 더 고칩니다.
   6. **입력 (코드):** 답변을 문항 칸에 넣고 들어간 글을 확인합니다. 전문은 `essays.md` 로 남깁니다.
5. **임시저장 (코드):** 설정의 저장 버튼 문구(임시저장, 중간저장 …)와 같은 버튼만 누릅니다. 제출 차단 가드가 그대로 적용됩니다. 뜬 알림 글도 기록합니다.
6. **검토 화면 띄우기:** 최소화된 창을 되돌리고 지원서 탭을 앞으로 가져온 뒤 알림을 보냅니다. 브라우저 창은 그대로 둡니다.
7. **Notion 정리:** 공고 페이지 본문에서 제목(절차 / 회사·조직 소개 / 지원 직무 / 자기소개서 질문 / 프로젝트 및 동아리 작성 여부 / 제출 자료 여부)을 찾아 그 아래에 내용을 넣습니다.
   - **이미 내용이 있는 섹션은 건드리지 않습니다.** 제목이 없으면 맨 끝에 제목과 함께 넣습니다.
   - 제출 상태를 "작성중"으로 바꿉니다 (DB 에 그 옵션이 없으면 바꾸지 않음). 끝까지 마치지 못했으면 바꾸지 않습니다.
   - 제목 이름은 설정 → Notion → "지원서 작성 후 채울 본문 제목"에서 내 템플릿에 맞춥니다.
8. **리포트:** 입력 요약, 비워둔 값, 참고사항, 자기소개서 검사 결과, 임시저장 결과, Notion 정리 결과, 막힌 동작, 화면 캡처를 `data/runs/…_apply-…/` 에 남깁니다.

Notion 정리만 다시 하려면:

```bash
autojob notion fill "<Notion 공고 페이지>" data/runs/<날짜>_apply-<회사>
```

브라우저 없이 자기소개서만 쓸 수도 있습니다:

```bash
autojob essay --company "회사명" --role "직무" --questions 문항.txt   # 문항은 빈 줄로 구분, "(700자 이내)" 처럼 제한 표기
```

추가 규칙, AI 모델과 **추론 성능**(낮음~최대), 동시 진행 개수는 설정 화면의 **작성 → 지원서 입력 규칙**에서 정합니다. 작업마다 모델·추론 성능을 한곳에서 보려면 **연결 → AI 연결 → 작업별 AI**. 기본 규칙 전문은 [prompts/fill-basic-info.md](prompts/fill-basic-info.md).

## Notion — `autojob notion`
설정 화면의 Notion 메뉴에서 토큰과 DB를 정한 뒤 씁니다. 화면의 "공고 1건 넣어보기"에서도 같은 일을 할 수 있습니다.

| 명령 | 설명 |
|---|---|
| `autojob notion test` | 토큰 연결 확인 |
| `autojob notion check` | 설정의 속성 이름, 옵션이 DB와 맞는지 검사 |
| `autojob notion list` | DB의 공고 목록 (마감 가까운 순) |
| `autojob notion add --company … --link … [--deadline …] [--roles …] [--employment …] [--type …] [--dry-run]` | 공고 1건 추가 |
| `autojob notion fill <페이지> <apply 실행 폴더>` | 지원서 작성 결과로 페이지 본문 정리 + 제출 상태 `작성중` (내용 있는 섹션은 둠) |
| `autojob notion bootstrap [--parent 페이지]` | 새 사용자용: 같은 구조의 DB를 새로 만들고 연결 |

- 페이지는 DB의 **기본 템플릿**으로 만듭니다. 템플릿이 없으면 설정의 제목들(절차, 회사/조직 소개 …)로 본문을 만듭니다.
- 직무, 채용 분류 같은 태그는 **DB에 이미 있는 옵션만** 넣습니다. 없는 값은 빼고 알려줍니다.
- **중복은 넣지 않습니다.** 지원 링크가 같거나, 회사명이 같고 마감일(또는 둘 다 상시)이 같으면 중복으로 봅니다. 회사명은 `(주)`, `[그룹명]` 등을 무시하고 비교합니다.
- 제출 상태는 기업 구분의 "작성중 표시"나 회사 직접 지정에 따라 정해집니다.

## 설정 — `autojob settings`
인자 없이 실행하면 메뉴가 열립니다. 바꾼 내용은 바로 `settings.yaml`에 저장되고, 형식이 틀리면 저장하지 않습니다.

| 메뉴 | 내용 |
|---|---|
| 검색 키워드 | 공고 검색어 추가/삭제 |
| 수집 사이트 | 사람인, 잡코리아, 원티드, 인크루트, 캐치, 자소설닷컴 켜고 끄기 |
| 고용형태 | 신입, 인턴, 채용연계형 인턴 등. 경력직 제외 여부 |
| 기업 구분 | 대기업, 유명IT, 금융, 공기업, 중견, 외국계, 스타트업, 중소를 포함할지, Notion에 "작성중"으로 둘지 |
| 회사 직접 지정 | 항상 포함, 항상 제외, 작성중으로 둘 회사 |
| Notion | 공고를 정리할 DB(링크 붙여넣기), DB 속성 이름, 옵션 이름 맞추기 |
| 자기소개서 문체 | 끝맺음, 소제목, 가운뎃점, 블라인드, 쓰지 않을 표현 |
| 브라우저 / 제출 차단 문구 / AI 연결 | 드라이버 선택, 차단 문구 목록, AI 연결 방식과 API 키 |

스크립트용 명령도 있습니다.

```bash
autojob settings show [경로]                       # 예: autojob settings show collect
autojob settings set browser.driver chrome
autojob settings add collect.keywords 백엔드 "Spring Boot"
autojob settings remove collect.keywords 백엔드
```

## 내 정보 — `autojob profile`
입력할 항목은 [profile/schema.yaml](profile/schema.yaml)에 정의되어 있습니다. 편집기, 검사, 빈 틀 생성, 지원서 자동 입력이 모두 이 파일을 따르므로, **항목을 추가하거나 바꾸려면 이 파일만 고치면 됩니다.**

| 명령 | 설명 |
|---|---|
| `autojob profile import [파일]` | 글을 붙여넣어 채우기 (파일, 또는 붙여넣고 Ctrl+D). 미리보기 → 적용할 섹션 선택 |
| `autojob profile edit [섹션]` | 대화형 편집기. 목록(대학교, 자격증, 자소서 소재 등)은 추가/수정/삭제 |
| `autojob profile show [섹션] [--filled]` | 입력한 내용 보기 |
| `autojob profile check` | 필수 항목, 날짜/연락처 형식, 정의에 없는 키(오타) 검사 |
| `autojob profile set <경로> <값>` | 값 하나 바로 넣기 |
| `autojob profile add <목록> key=값 ...` | 목록에 항목 추가 |
| `autojob profile remove <목록.번호>` | 목록 항목 삭제 |
| `autojob profile schema` | 입력 가능한 항목과 경로 보기 |

```bash
autojob profile set basic.phone 010-1234-5678
autojob profile add extras.certificates name=정보처리기사 date=2025.06.13
autojob profile remove extras.certificates.0
```

섹션: `basic`(기본정보), `education`(학력/연구), `career`(경력/교육/NCS), `extras`(어학/자격/기타), `target`(희망 조건), `stories`(자소서 소재), `notes`(지원서 입력 메모 — 비워 둘 칸, 항목별 지시)

- 연월 칸에는 일까지 적어도 됩니다 (`2019.03.02`). 사이트가 월까지만 받으면 AI 가 잘라서 넣습니다.
- 링크의 "그 밖의 링크"에 "언제 쓰나"(예: 클라우드 직무)를 적으면 지원 직무에 맞는 것만 넣습니다.

- 값이 없는 항목은 비워 두세요. AI는 빈 값을 추정해서 채우지 않습니다.
- 증명사진 같은 파일은 `profile/me/files/`에 넣고 파일 이름을 입력합니다.
- `profile/me/*.yaml`을 직접 편집해도 됩니다. 저장할 때 주석은 보존됩니다.

## 브라우저와 제출 차단

| 명령 | 설명 |
|---|---|
| `autojob browser open [url]` | 자동화 전용 프로필로 브라우저 열기. 채용 사이트에 미리 로그인해 두면 유지됨 |
| `autojob browser test` | 가짜 지원서로 입력 기능과 제출 차단 검증 |

- 평소 쓰는 브라우저 프로필과 분리된 **자동화 전용 프로필**(`~/.autojob/browser-profiles/`)을 씁니다. Aside 와 Chrome 은 보안 정책상 **기본 프로필에서는 원격 조종을 켤 수 없어서**(쿠키를 훔치는 악성 프로그램 방지) 기본 프로필을 직접 쓰지는 못합니다.
- 대신 설정 → 브라우저의 **"가져오기"**로 평소 프로필에 저장된 **비밀번호**와(원하면) **로그인 상태(쿠키)**를 자동화 프로필로 복사할 수 있습니다. 비밀번호가 있으면 로그인 칸이 자동 완성되고, 로그인 상태까지 가져오면 이미 로그인된 사이트는 로그인 자체를 건너뜁니다. 암호화된 채로 복사되고 이 도구는 내용을 보지 않습니다. 평소 프로필은 그대로 두고 복사만 하며, 자동화 프로필에 원래 있던 파일은 `.bak` 으로 남습니다.
- 제출 차단은 3중입니다.
  1. 페이지 안에서 금지 문구 버튼 클릭과 폼 제출을 막음
  2. 클릭 명령이 누르기 전에 문구를 검사해 거부
  3. 뒤로가기, 새로고침, 페이지 나가기 차단

## 점검 — `autojob doctor`
Node.js, 설정 파일, 내 정보(필수 항목), 검색 조건, Notion, 브라우저, AI 연결을 점검하고 다음 할 일을 알려 줍니다. `--ai` 를 붙이면 AI 에게 짧은 질문을 보내 실제로 답하는지도 봅니다.

## 개인 데이터
내 정보와 설정은 **내 컴퓨터에만** 저장됩니다. 서버로 보내는 곳은 없고, AI 연결과 Notion 처럼 직접 연결한 곳에만 요청이 나갑니다.

| 어디에 저장되나 | 언제 |
|---|---|
| 내려받은 저장소 폴더 | 이 저장소를 `git clone` 해서 쓰는 경우 (`.git` 이 있거나 이미 `settings.yaml` 을 만든 경우) |
| `~/.autojob/` | 그 밖의 설치 (예: `npm i -g`) — 설치 폴더에 개인 데이터를 쓰지 않습니다 |
| `AUTOJOB_HOME` 이 가리키는 폴더 | 환경 변수를 지정한 경우 (여러 벌로 쓰거나 테스트할 때) |

`settings.yaml`, `profile/me/`, `data/`, `.env` 는 git 에 올라가지 않습니다. 리포트와 화면 캡처(`data/runs/`)에도 개인정보가 들어가므로 공유하지 마세요.
