# 지원서 에이전트 검증

2026-09-17 KST. Auto-Job의 공고 수집, 프로필 편집, AI 연결, 회사별 대화방을 유지하면서 지원서 실행 구조를 교체했습니다. 개인 자료 기반 검색은 [SEARCH_VALIDATION.md](SEARCH_VALIDATION.md)에 별도로 기록했습니다.

## 브라우저 도구 교체 (2026-09-17)

지원서 실행은 Microsoft 공식 `@playwright/mcp` 0.0.81을 사용합니다. MCP가 요구하는 Playwright 1.64.0-alpha-2026-09-14 버전을 함께 고정했습니다. 자체 `ApplyTools`, `browserToolset`, DOM `data-autojob-ref` 스냅샷 구현을 제거했습니다. 기존 자체 도구를 시험하던 `smoke-conversation-browser.ts`도 공식 MCP 회귀 시험으로 교체했습니다.

실제 NH 지원서의 **필드 속성만 읽어서** 두 원인을 확인했습니다. 일반 경력·자격증·어학 등록번호 입력에도 `autocomplete=one-time-code`가 붙어 있었고, 자격증 복제 행에는 자체 `data-autojob-ref` 속성이 중복돼 있었습니다. 폼 값은 변경하지 않았습니다. 이제 요소 식별, 접근성 화면, 일괄 입력, 선택, 좌표 조작은 공식 MCP가 수행하며, autocomplete 힌트 하나로 일반 입력을 인증으로 분류하지 않습니다.

교체 후 같은 실제 지원서를 공식 MCP로 읽기만 했으며, 반환된 요소 ref 735개가 전부 고유하고 이전 `f0-숫자` 참조가 노출되지 않는 것을 확인했습니다. 실제 입력·저장 성공 증거는 아래의 합성 폼 시험에 한정됩니다.

Auto-Job 어댑터는 작업 탭과 그 팝업만 MCP에 노출하고, 실행 토큰·중지·첨부파일 범위·인증 비밀값·최종 제출 경계를 관리합니다. 임의 코드 실행 및 네트워크/저장소 도구는 지원서 에이전트에 노출하지 않습니다. 자연어 요청을 작업 명령으로 정규식 분기하지 않습니다. 기존 저장 버튼 문구 목록은 설정 파일 호환용으로만 남겼으며 화면에서 AI가 버튼을 선택합니다.

## 현재 구조

대화 AI가 작성 단계를 예약하고 별도 파이프라인을 실행하던 구조를 제거했습니다. 같은 에이전트가 최신 요청·기존 대화·내 정보·연결 자료·실제 화면을 읽고, 필요한 작업 순서와 도구를 선택합니다. 기존 `basic`/`essay` 옵션은 요청 범위로만 전달됩니다. 별도로 실행하는 `autojob essay` CLI는 기존 작성·검수 과정을 유지합니다.

- 파일은 연결된 폴더의 목록에서만 읽습니다. md/txt/PDF를 지원하며 긴 내용은 나눠 읽습니다. 자료와 웹페이지는 참고 데이터입니다.
- 문항 기록, 글자수·문체 검사, 답변 입력, 회사 정보 기록은 에이전트가 필요에 따라 사용하는 도구입니다. 고정된 조사·전략·작성·검수 순서를 강제하지 않습니다.
- 자연어 메시지를 정규식으로 분류하지 않습니다. 질문에는 같은 AI가 문맥을 읽고 답합니다.
- 예시·각색 요청에는 가정을 밝힌 초안을 먼저 작성합니다. 제안한 방향에 동의하는 짧은 답변도 대화 맥락으로 이어받습니다. 기존의 일괄적인 사실 생성 금지를 이 구분으로 바꿨으며, 가정을 확인된 프로필 사실로 기록하지 않도록 했습니다.
- 학교·자격증 등의 클릭 가능한 표 행, 달력의 연·월, 일반 버튼 외의 커스텀 선택지를 지원합니다. 좌표 클릭에도 제출 차단을 적용합니다.
- 기존 사용자 입력을 보존하라는 작업 지침은 유지합니다. 자료로 확인되는 기본값 오류·잘림은 AI가 스스로 정정하며, 모든 비어 있지 않은 칸을 잠그던 코드와 자소서 수정 시 요청을 그대로 인용해야 하던 조건은 제거했습니다.
- 화면 스냅샷에 입력 요소뿐 아니라 안내·문항·저장 결과 글도 포함합니다. 비밀번호와 OTP 값은 텍스트와 화면 이미지에서 가립니다.
- 임시저장은 버튼 클릭과 성공 확인을 구별합니다. `browser_click`과 좌표 클릭 모두 실제 저장 시도의 화면 변화와 알림을 관찰합니다. 반복 저장으로 같은 성공 문구가 다시 표시되는 경우도 확인할 수 있습니다.
- 완료·미완료·질문 답변을 구분합니다. 전체 작성 요청에서 필수 입력·저장 확인이 남으면 완료로 표시하지 않습니다. 일부만 처리하거나 저장하지 말라는 요청은 그 범위를 따릅니다.
- 새 메시지와 중지는 해당 회사의 실행 토큰만 폐기합니다. 시작된 호출의 정리를 기다리고 이전 실행의 대기 호출과 늦은 결과를 거절합니다.
- 재접속할 브라우저가 꺼져 있으면 기존 포트·프로필로 다시 켭니다. 원래 탭 ID 또는 유일한 작업 식별자로 복구하고, 둘 다 없으면 다음 이어가기 요청에서 해당 회사 전용 새 창을 만듭니다. 같은 주소라는 이유로 다른 탭을 사용하지 않습니다. 저장되지 않은 입력은 브라우저 종료 후 사라질 수 있으며, 복구 후에는 실제 화면을 다시 읽습니다. 최종 제출 기능은 없습니다.

### 초안 요청의 반복 질문 재현

`smoke-application-drafting.ts`는 실제 Codex와 합성 context·브라우저 도구로 두 대화를 재현합니다. “4번 지어내줘”에는 629자, 제안된 방향에 “ㅇㅇ 지금 너가 말한 그런느낌이야”라고 답한 경우에는 708자 초안을 작성했습니다. 두 경우 모두 `ask_user` 호출은 0회였고 가정/창작임을 사용자에게 밝혔습니다. 실제 지원서나 브라우저에는 입력하지 않았습니다. 결과는 `data/verification/application-drafting.json`에 있습니다. 관련 단위·통합 테스트 23개와 typecheck도 통과했습니다. 이 재현은 두 응답의 증거이며 모든 모델에서 같은 문장을 보장하지 않습니다.

### Notion 정리를 대화 AI에 연결

기존에는 `applyNow`가 AI 종료 뒤에만 `fillPageSections`를 호출했고, 질문 답변과 인증 대기에서는 실행되지 않았습니다. AI에 본문 조회·편집 도구가 없어 "도구가 없다"고 답했던 원인입니다. 이 사후 처리를 제거하고 같은 에이전트에 연결된 공고 페이지의 읽기·블록 추가·수정·작성 상태 변경·재확인 기능을 제공했습니다. 기존 `autojob notion fill` CLI는 별도로 유지합니다.

- 읽은 페이지 안의 블록만 수정하며 이동된 블록·하위 페이지·다른 공고는 거절합니다. 기존값 비교로 동시 수정을 감지하고 같은 추가 요청의 재시도는 중복하지 않습니다.
- API 쓰기 응답뿐 아니라 본문 재조회 결과를 확인합니다. 최종 `notion_verify` 결과와 사이트 임시저장은 별개이며, 인증 대기로 실행이 중단되어도 노션 결과는 다음 대화에 남습니다.
- 단위·통합 검증에는 403, 반영되지 않은 쓰기, 쓰기는 성공했으나 응답이 유실된 경우, 변경 충돌, 중지, 기존 메모 보존, 작성 상태 확인이 포함됩니다.
- 실제 Codex + 합성 브라우저/Notion API 재현에서 1~5번 전문·가정 표시·저장 실패 상태 기록과 재조회를 확인했습니다. 다만 최초 완료 표시가 전체 지원서 범위와 섞여 보완했으며, 이후 실제 AI 재실행은 응답 지연으로 시간 제한에 도달했습니다. 이 재현을 전체 통과로 보고하지 않습니다. `smoke-application-notion.ts`는 합성 API만 사용합니다.
- 블록 갱신과 위치 지정은 [Notion 블록 수정 API](https://developers.notion.com/reference/update-a-block), [자식 블록 추가 API](https://developers.notion.com/reference/patch-block-children)에 맞췄습니다.

### 한화 실행의 입력 잠금과 보고 오류

실행 리포트의 안내 확인칸 원문은 `.` 입력을 허용했습니다. 이 입력 자체는 오류가 아니지만 모든 textarea를 자소서로 기록해 소제목·90% 분량 검사를 적용하고 자소서 2/2 완료로 표시했습니다. AI가 `essay` / `notice` / `short_answer`를 구분해 기록하도록 하고, 길이·공란 검사는 유지하면서 비자소서 문체 검사를 제외했습니다. 리포트 집계도 분리했습니다.

일반 입력·선택의 기존값 일괄 잠금을 제거했습니다. 기본값, 자동 잘림, 화면 재생성으로 ref가 바뀐 입력도 공식 MCP로 수정할 수 있습니다. 사용자 입력 보존은 요청 범위와 자료에 따라 AI가 판단하며 비밀번호·작업 탭·최종제출 경계는 유지합니다. `finish`에서 미입력 항목을 기록할 수 있게 했고, 기록이 없으면 빈칸이 없다고 단정하지 않습니다. 도구 실패는 입력 내용을 가린 오류 사유를 남깁니다.

실제 한화 지원서는 쓰기 시험에 사용하지 않습니다. 해당 실행의 저장 성공 기록과 다음 단계 안내는 과거 관측이며, 이번 코드 수정이 실제 지원서의 값을 고쳤다는 뜻은 아닙니다.

실제 Chrome 합성 폼에서 기존 이메일 수정, 병역 기본값 수정, 체크 상태 변경, 글자 제한으로 잘린 교육 설명을 화면 재생성 후 새 ref로 수정하는 회귀 시험을 통과했습니다. 기존 입력을 읽는 것만으로 값이 변하지 않는지, 인증값 마스킹·최종제출 차단이 계속 동작하는지도 확인했습니다. 증거는 `data/verification/playwright-mcp.json`입니다.

### Aside 패널 선택과 모델 설정

Auto-Job을 기본으로 유지하고 새 지원서/기존 대화에서 Aside 패널로 넘기기를 추가했습니다. 현재 실행 정리를 기다린 뒤 자료를 생성하며, Aside 모드에서는 Auto-Job 실행/중지가 동작하는 것처럼 표시하지 않습니다. 자료 준비 실패 시 전환 성공으로 기록하지 않습니다. 내 정보·자료 경로·대화·Notion 정리 요청은 내보내되 AI 연결 설정과 자격 증명 저장소는 포함하지 않습니다.

설치된 Aside 1.26.810.1915의 공식 CLI 도움말과 Aside 내장 스킬의 `aside.sessions` API를 확인했습니다. `aside exec`의 실제 AI 응답과 같은 세션의 후속 응답은 확인했으나, 실행 CLI에 SIGINT를 보내도 네이티브 세션은 계속 `running` 상태였습니다. 따라서 이 CLI를 Auto-Job의 취소 가능한 실행 엔진으로 연결하지 않았습니다. 사용자가 실제 Ask Aside 패널에 요청을 붙여넣어 진행하는 선택 기능이며 패널 제어·자동 결과 동기화는 구현 범위가 아닙니다.

UI 합성 API 시험에서 기존 대화 전달, 클립보드 복사, 선택한 회사로 Aside 열기 요청, Auto-Job 복귀 시 초안 유지, 새 지원서의 기본/Aside 선택을 확인했습니다. 실제 macOS Aside 열기 함수는 고유 표시가 있는 localhost 검증 탭으로 확인한 뒤 그 탭만 닫았습니다. 실제 회사 지원서나 사용자 Notion에 쓰지 않았습니다. 전달 후 Aside에서의 지원서 전체 작성 결과는 검증하지 않았습니다.

Codex 어댑터의 `xhigh`·`max`를 `high`로 낮추는 오래된 변환을 제거했습니다. 설정한 추론 수준을 그대로 CLI에 전달하며, 모델이 지원하지 않는 값은 오류로 알리고 몰래 낮추지 않습니다. 이것은 전달 인자 검증이며 모든 모델의 모든 추론 수준을 실제 실행했다는 뜻은 아닙니다. Auto-Job과 Aside가 같은 모델이라고 가정하지 않습니다.

## 확인하지 않은 범위

- 실제 NH농협손해보험 지원서와 사용자 Notion에는 쓰기 시험을 하지 않았습니다. 기존 기업 지원서는 중지 상태를 유지했습니다.
- 모든 채용 사이트에서 끝까지 완료한다는 보장은 아닙니다. 기업별 인증, 업로드, 다단계 페이지, 특수 위젯은 실제 포털에서 추가 확인이 필요합니다.
- Aside 시험은 실제 설치된 앱의 별도 임시 프로필을 headless로 실행했습니다. 사용자의 일상 프로필이나 Aside 내장 AI를 조작한 시험은 아닙니다.
- 실제 AI 시험은 공식 Playwright MCP를 통한 Codex 실행입니다. Anthropic/OpenAI API와 Claude CLI는 공통 인터페이스 자동화 검사 범위이며 이번 변경의 실제 계정 시험은 하지 않았습니다.
- 글자수와 화면 입력은 검사했지만 합성 경험 한 건으로 실제 기업별 자소서 품질까지 입증하지는 않습니다.

## 재현

Node.js 22 이상, macOS 기준입니다. 실제 AI 시험은 Codex 사용량을 소비합니다.

```sh
npm test
npm run typecheck
node --check src/web/app.js
git diff --check
# 실제 Codex + 임시 Aside 프로필 + localhost 합성 지원서
node --import tsx test/smoke-application-agent.ts
# 실제 AI 없는 브라우저 회귀, 별도 Chrome 프로필
node --import tsx test/smoke-playwright-mcp.ts
# 브라우저 프로세스를 실제 종료·재시작하는 복구 검사
node --import tsx test/smoke-browser-recovery.ts
# 합성 응답으로 UI 검사
node --import tsx test/smoke-conversation-ui.ts
# 실제 Codex, 합성 대화/도구로 각색 요청과 짧은 동의 재현 (실제 브라우저 미사용)
node --import tsx test/smoke-application-drafting.ts
# 실제 Codex, 합성 Notion HTTP API와 화면으로 정리 및 후속 수정 확인
node --import tsx test/smoke-application-notion.ts
```
