# 개인 자료 기반 공고 검색 검증

2026-09-17 KST. Auto-Job의 검색 키워드를 선택 사항으로 바꾸고, 공고 수집 전에 사용자별 자료 분석을 추가했습니다.

## 동작

- CLI와 설정 화면 모두 현재 사용자의 프로필과 `stories.folders`를 읽어 검색 계획을 만듭니다. 연락처만 있는 프로필은 검색 근거로 보지 않습니다.
- md/markdown/txt와 로컬 `pdftotext`로 추출한 PDF 내용을 모든 AI 연결에 같은 방식으로 전달합니다. 긴 내용은 앞부분만 자르지 않고 여러 번에 나눠 분석합니다. 파일 및 폴더 설명도 출처로 구별합니다.
- AI가 추출한 인용이 실제 입력 자료에 있는지 확인합니다. 확인된 근거 ID를 인용한 직무만 검색 방향으로 채택합니다. 문서의 명령을 실행하지 않도록 지시하고 분석 에이전트에 도구를 주지 않습니다.
- 자동 검색어는 최대 12개이며 직접 입력한 추가 검색어와 합쳐 수집기에 전달합니다. 저장된 키워드와 사이트별 직무 분류, 기업 구분 등 필터는 유지합니다.
- 수집 결과에 실제 검색어, 선정 이유, 근거와 미처리 자료를 표시합니다. 프로필 이름·연락처·주소·등록번호는 검색 문맥에서 제외합니다. 사용자가 연결한 파일 내용에는 별도 개인정보 제거를 적용하지 않으며 선택한 AI로 전달됩니다.
- 개인 자료가 없고 수동 조건만 있으면 수동 검색임을 알립니다. 개인 자료 분석 실패를 고정 직무나 수동 검색으로 조용히 대체하지 않습니다.
- 읽기 제한은 파일당 8MB, 폴더당 400개·깊이 6단계이며 누락을 경고합니다. 전체 입력 120만 자 또는 추출 근거 20만 자를 넘으면 범위를 줄이도록 안내하고 검색을 중단합니다.
- 개인 자료가 들어 있는 AI 임시 작업 폴더는 성공·실패 후 삭제합니다. 실행 결과 리포트는 `data/runs/`에 권한 600으로 저장합니다.

## 직접 확인한 근거

| 검증 | 결과 |
| --- | --- |
| Node 22 단위·통합 검사 | `npm test`: 152개 통과. 키워드 없이 자료 분석, 실제 수집기 인자 전달, 수동 설정 보존, 긴 파일 끝부분 사용, 자료 수정 반영, 중복 폴더, 외부 symlink 제외, PDF 실패 안내, 원문에 없는 근거 거절, 실패 시 임의 검색 방지, doctor 안내 포함. AI 응답과 수집기는 해당 테스트에서 주입했습니다. |
| 타입·정적 검사 | `npm run typecheck`, `node --check src/web/app.js`, `git diff --check` 통과. |
| 실제 Codex | 서로 다른 합성 자료 폴더 2종으로 실행했습니다. 회계 인턴 프로필에는 회계·재무·정산, 디자인 프로필에는 UX/UI·프로덕트 디자인 검색어를 생성했습니다. 입력 키워드는 모두 비어 있었습니다. |
| 자료 구분 | 각 합성 폴더에 개발 경력 10년을 요구하는 제3자 공고와 지시문 예시를 함께 두었습니다. 실제 Codex 결과는 이를 본인의 경력으로 채택하지 않고 각자의 직무 희망과 개인/팀 역할을 구별했습니다. |
| 실제 PDF | 합성 PDF의 텍스트 레이어를 로컬 `pdftotext`로 추출했습니다. |
| UI | 별도 Chrome과 임시 프로필에서 선택 표시, 빈 검색어 안내, 미리보기의 직무별 근거 표시를 확인했습니다. 수집 응답은 위 실제 Codex 계획을 담은 합성 응답입니다. 데스크톱·모바일 캡처를 확인했고 JS 오류는 없었습니다. |

합성 결과와 캡처는 Git에서 제외한 `data/verification/search-*`에 저장했습니다.

## 미검증 범위

- 실제 사용자의 자료, 기업 지원서, 사용자 Notion DB로 쓰기 시험을 하지 않았습니다.
- 실제 채용 사이트에서의 최신 공고 수, 검색 재현율, 개인별 추천 품질 또는 모든 지원 자격 충족을 입증하지 않습니다. 수집기의 기존 검색·필터 로직을 사용하며 공고별 AI 적합성 심사는 이번 변경에 포함되지 않습니다.
- 이번 자료 분석의 실제 계정 시험은 Codex CLI에서만 수행했습니다. Claude CLI 및 Anthropic/OpenAI API는 공통 호출 형식과 테스트 주입으로 검사했습니다.
- 스캔 PDF의 OCR은 수행하지 않습니다. 지원하지 않는 파일 확장자는 기존 폴더 스캐너와 같이 제외합니다.
- 원문 인용 검사는 출처 존재를 검사합니다. AI의 모든 해석이나 추론이 사실임을 보장하는 검사는 아닙니다.

## 재현

Node.js 22 이상, Chrome, Codex CLI 로그인, Poppler가 필요합니다. 일반 테스트는 개인 설정과 토큰을 제외한 임시 폴더에서 실행합니다.

```sh
npm test
npm run typecheck
node --check src/web/app.js
# 실제 Codex 사용량 소비. 합성 자료·PDF·UI만 사용하며 실제 채용/Notion 쓰기 없음
node --import tsx test/smoke-search.ts
```
